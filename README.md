# Northwind Sales Insights with dbt

## Business Problem

Northwind Trading stores its operational data in several raw tables. The raw data contains inconsistent column names and data types. Without a structured transformation layer, analysts would need to repeatedly write complex SQL joins and could calculate revenue differently.

This dbt project cleans, transforms, and aggregates the Northwind sales data into business-ready models.

## Models

### Staging

The staging models clean and standardize the raw Northwind data:

* `staging_orders.sql` – cleans order information and standardizes column names and dates.
* `staging_order_details.sql` – cleans order line information and converts numeric fields.
* `staging_products.sql` – standardizes product and category information.
* `staging_categories.sql` – standardizes product category information.

### Prep

* `prep_sales.sql` – joins the staging models and creates a consolidated sales dataset. It also calculates revenue, order year, and order month.

### Mart

* `mart_sales_performance.sql` – aggregates sales by year, month, and product category. It provides total revenue, total orders, and average revenue.

## Business Insights

The final mart can be used by Northwind to analyze:

* revenue development over time
* sales performance by product category
* the number of orders per month and category
* average revenue generated by sales records
* changes in category performance across different months and years

These metrics provide a consistent dataset that can be used by dashboards and other analytics.

## Biggest Learning

The biggest learning moment was understanding how dbt separates data transformation into different layers. Staging models clean the raw data, the prep model combines the cleaned data and applies business logic, and the mart model creates an aggregated dataset for analysis.

I also learned how `source()` is used to reference raw database tables and how `ref()` creates dependencies between dbt models.
